## 1. Purpose

This document describes the process used to record,
track and report defects identified during manual
testing of the SauceDemo application.

## 2. Defect Reporting Fields

Each identified defect should contain:

| Field | Description |
|---|---|
| Defect ID | Unique defect reference |
| Defect Title | Short description of the issue |
| Module | Application area affected |
| Environment | Browser and operating system |
| Steps to Reproduce | Steps required to reproduce the issue |
| Expected Result | Expected application behaviour |
| Actual Result | Observed application behaviour |
| Severity | Impact of the defect |
| Priority | Urgency of fixing the defect |
| Status | Current defect status |

## 3. Severity Definitions

| Severity | Description |
|---|---|
| Critical | Application crash or major business functionality unavailable |
| High | Important functionality significantly affected |
| Medium | Functionality affected but workaround may exist |
| Low | Minor visual or usability issue |

## 4. Priority Definitions

| Priority | Description |
|---|---|
| P1 | Fix immediately |
| P2 | Fix with high priority |
| P3 | Fix when scheduled |

## 6. Defect Status

No confirmed defects were recorded during the
test cases executed in this testing exercise.

This does not establish that the entire application
is defect-free. Further testing may identify
additional issues.

## 7. Conclusion

All observed behaviours were recorded against
their expected results.

Any future defects identified during additional
testing will be documented using the defect
reporting fields defined in this document.
