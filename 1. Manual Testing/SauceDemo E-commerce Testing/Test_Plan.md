## 1. Introduction

This document describes the testing approach, scope,
objectives, resources and activities required to test
the SauceDemo e-commerce web application.

The purpose of this project is to evaluate the
application's functionality and identify defects
through manual testing.

## 2. Objectives

The main objectives of this testing project are:

- Verify that users can log in and log out successfully.
- Validate product listing and sorting functionality.
- Verify adding and removing products from the cart.
- Validate the checkout process.
- Verify mandatory field validations.
- Identify functional defects and usability issues.
- Ensure that critical user journeys work as expected.

## 3. Scope of Testing

### 3.1 In Scope

The following application features will be tested:

1. Login functionality
2. Product inventory page
3. Product sorting
4. Product details
5. Add to cart
6. Remove from cart
7. Shopping cart
8. Checkout information
9. Order overview
10. Order completion
11. Logout functionality
12. Error messages and validations

### 3.2 Out of Scope

The following areas are excluded from this project:

- Real payment gateway integration
- Actual financial transactions
- Production server performance
- Security penetration testing
- Third-party integrations
- Mobile application testing

## 4. Test Approach

Testing will be performed manually using a web browser.

The following testing techniques will be used:

- Functional Testing
- Positive Testing
- Negative Testing
- Boundary Value Analysis
- Equivalence Partitioning
- Exploratory Testing
- Regression Testing
- End-to-End Testing

Actual browser and application versions will be

## 6. Test Data

Test data will include:

- Valid login credentials
- Invalid login credentials
- Empty username and password
- Valid checkout information
- Missing checkout information
- Different product selections
- Different shopping cart combinations

Only publicly provided demo accounts and
non-sensitive test information will be used.

## 7. Entry Criteria

Testing can begin when:

- The application is accessible.
- The test environment is available.
- Test scenarios and test cases are prepared.
- Required test data is identified.

## 8. Exit Criteria

Testing will be considered complete when:

- All planned test cases have been executed.
- Actual results have been documented.
- Defects have been recorded.
- Critical defects have been reviewed.
- A test summary report has been prepared.

## 9. Defect Management

Any unexpected behaviour identified during testing
will be documented as a defect.

Each defect report will include:

- Defect ID
- Defect Title
- Description
- Steps to Reproduce
- Expected Result
- Actual Result
- Severity
- Priority
- Status
- Supporting Evidence

## 10. Risks and Mitigation

| Risk | Mitigation |
|---|---|
| Demo website unavailable | Retry testing later |
| Application behaviour changes | Record test environment details |
| Test data issues | Validate test data before execution |
| Time limitations | Prioritise critical user journeys |

## 11. Deliverables

The following documents will be produced:

1. Test Plan

3. Detailed Test Cases
4. Test Execution Report

6. Test Summary Report
